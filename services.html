What is Switchable Graphics Technology?

Switchable Graphics is a laptop technology that utilizes both the graphical processing capabilities of a discrete graphics adapter and the power efficiency of an integrated graphics adapter. It engages discrete graphics only when it is needed for 3D applications, and uses energy-efficient integrated graphics capabilities the rest of the time.

How to Enable Switchable Graphics?

To ensure full compatibility it is recommended to use the latest graphics driver for the integrated and high performance AMD graphics processor (GPU) provided by the laptop manufacturer. Switchable Graphics will not function if the power saving GPU does not have display drivers installed.

To use the most recent original driver, execute in exact sequence:

  1. Install the latest Intel graphics driver from the Intel or laptop manufacturer's website.
  2. Install the latest AMD graphics driver from the AMD or laptop manufacturer's website.

Note: Before installing display drivers, check windows device manager to see if the GPUs are listed under Display Adapters. The high performance GPU may appear under other devices as a generic video controller.

Configuring Settings

  1. Right-click the Desktop and select AMD Radeon Settings from the menu.
  2. Select Preferences.
  3. Select Radeon Additional Settings.
  4. Navigate to Power and select Switchable Graphics Application Settings to inspect application mapping.
  5. Select Switchable Graphics Global Settings to adjust profiles for battery deployment.

Assigning Applications to High-Performance GPUs

Navigate to Radeon Settings > Preferences > Additional Settings > Power > Switchable Graphics Application Settings, then click Add Application. Select the targeted binary file and choose High Performance under Graphic Settings, then apply.

Environment Scenario: Dell PowerEdge 2950 host running three logical guest Hyper-V Virtual Machines. Upgrading systems BIOS and Broadcom (BCM) NIC device drivers can cause virtual machine adapters to lose operational connectivity post-reboot.

Symptom: The structural bindings on the logical Virtual Switch state unselect themselves inside system administration views and fail to toggle back on natively.

Operational Resolution Flow:

  1. Launch the Hyper-V Control Panel. Open the Virtual Network Manager application configuration page.
  2. Toggle the target Local Area Network interface state assignment from External over to Private, then commit with Apply.
  3. Navigate back out to bare-metal OS adapter settings properties. Locate the physical Broadcom interface; if Windows has applied the virtual binding check box to the hardware adapter properties natively, uncheck it completely.
  4. Return to the Virtual Network Manager interface and set properties safely back to External. The Virtual Switch will bind cleanly and VM adapters will regain line sight immediately.
